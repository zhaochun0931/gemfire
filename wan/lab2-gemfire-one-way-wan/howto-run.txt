The Rules of Multiple Serial Senders
On the Cluster Level: You can define as many unique serial gateway senders as you want in Cluster 1 (e.g., sender-A, sender-B, sender-C).

On the Region Level: A single GemFire region can only use one serial gateway sender at a time. If you try to attach two different serial senders to the exact same region, GemFire will throw an error.






On the receiving side (Cluster 2), the gateway receiver architecture is incredibly simple: you only need a single gateway receiver per cluster member. You do not need to create multiple receivers to match your multiple serial senders. A single gateway receiver is fully capable of handling traffic from many different gateway senders simultaneously.

How It Works Behind the Scenes
Think of the gateway receiver as a multi-lane toll booth with a single open gate.

The Senders (Cluster 1): Each serial gateway sender creates its own separate queue and TCP connection pool.

The Receiver (Cluster 2): The gateway receiver listens on a range of ports (by default, 50504 through 50604).

When you start multiple serial senders on Cluster 1, they will all reach out across the network and establish their own individual TCP connections to Cluster 2's receiver. The receiver automatically handles the multiplexing—it accepts the incoming streams from all the different senders, processes the data, and applies it to the correct local regions.









One-Way (Active-Passive) WAN replication topology.

In this setup, data flows strictly from Cluster 1 (the source/active site) to Cluster 2 (the target/passive site).

Changes made in Cluster 1 will replicate to Cluster 2, but Cluster 2 will not replicate anything back to Cluster 1.



Step 1: Configure Cluster 2 (The Receiver)


You must always start the receiver side first so that when the sender starts up, it has something to connect to.



# 1. Connect to Cluster 2:

docker exec -it cluster2-locator gfsh

connect


# 2. Create the receiver (this tells the cluster to listen for incoming WAN traffic):

create gateway-receiver


# 3. Create the hosting region without a gateway sender attached:

create region --name=region1 --type=REPLICATE
create region --name=region2 --type=REPLICATE










Step 2: Configure Cluster 1 (The Sender)

Now, set up Cluster 1 to push data out.

# 1. Connect to Cluster 1:

docker exec -it cluster1-locator gfsh


# 2. Create the gateway sender pointing to Cluster 2 (System ID 2):

create gateway-sender --id=sender-for-region1 --remote-distributed-system-id=2

create gateway-sender --id=sender-for-region2 --remote-distributed-system-id=2


# 3. Create the region and attach the gateway sender to it:

create region --name=region1 --type=REPLICATE --gateway-sender-id=sender-for-region1

create region --name=region2 --type=REPLICATE --gateway-sender-id=sender-for-region2






Step 4: Test with Data Entries
Now, let's write unique entries into both regions on Cluster 1 and see them map across the independent queues.

Insert data into Cluster 1:

docker exec -it cluster1-locator gfsh

connect


put --region=/region1 --key="R1-01" --value="Data for Region 1"
put --region=/region1 --key="R1-02" --value="More Data for Region 1"

put --region=/region2 --key="R2-01" --value="Data for Region 2"
put --region=/region2 --key="R2-02" --value="More Data for Region 2"




Step 5: Verify Data on Cluster 2
Connect back to Cluster 2:


docker exec -it cluster2-locator gfsh

connect

query --query="select * from /region1"


query --query="select * from /region2"
